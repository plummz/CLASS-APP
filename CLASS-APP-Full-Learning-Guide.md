## 1. App Overview

### What is CLASS-APP?

CLASS-APP is a **school portfolio web application** built for college IT students. It runs in a browser (on phones, tablets, or computers) and can also be installed on a phone's home screen like a real app (this is called a **PWA** — Progressive Web App).

Think of it as a private school dashboard where students can:
- View and organize class files
- Read and share study reviewers
- Summarize uploaded documents using AI
- Chat with classmates in real time
- Play browser games between study sessions
- Listen to music
- Set alarms and keep notes
- Track class schedules and announcements

### What type of app is it?

| Type | Yes/No | Explanation |
|------|--------|-------------|
| Web App | ✅ | Runs in a browser at a URL |
| PWA | ✅ | Can be installed on phones like an app |
| Mobile-First | ✅ | Designed primarily for phones |
| iOS + Android | ✅ | Works on both |
| Real-Time App | ✅ | Chat and lobby update instantly |
| AI-Powered | ✅ | File summaries and quizzes generated by AI |
| Multi-User | ✅ | Multiple students can log in |

### Main Features

1. **My Classes** — Year 1 to Year 4, First and Second Semester folders
2. **File Manager** — Upload, organize, view, and download files in folders
3. **File Summarizer** — Upload a PDF/DOCX/PPTX and get an AI summary or quiz
4. **Shared Reviewer** — Students share and vote on study notes
5. **AI Assistants** — Chat with Gemini or Groq AI models
6. **Coding Lessons** — Interactive coding lessons with a built-in code lab
7. **Chat** — Real-time group and private messaging via Socket.IO
8. **Calendar** — Personal calendar with sticky notes per date
9. **Music Hub** — Search and play YouTube music
10. **Games** — Pokémon battle, Battle Royale, Candy Match, Pac-Man, Tetris, Lobby platformer
11. **Personal Tools** — Alarm clock, Notepad, Scientific Calculator, Personalization
12. **User Directory** — See who is online
13. **Announcements** — Admin-posted announcements
14. **Social Media** — Embedded Facebook page view
15. **Software Update** — Changelog of every version update
16. **Admin Panel** — Admin-only tools (diagnostics, user management)

### How the App is Connected (System Flow)

```
 [Student's Phone/Browser]
        |
        | opens URL (e.g., https://class-app.onrender.com)
        v
 [index.html] ← loads CSS (style.css) + JS (script.js, feature files)
        |
        | on page load → fetches /api/config
        v
 [server.js — Express Backend on Render.com]
        |
        |── /api/login  ──────────────► [bcrypt + JWT] → token stored in localStorage
        |── /api/summarize-file ──────► [Gemini AI / Groq AI] → returns summary
        |── /api/yt-search ───────────► [YouTube API] → music results
        |── /uploads/* ───────────────► [Cloudflare R2] → files served
        |── Socket.IO ────────────────► [Real-time chat and lobby events]
        |
        v
 [Supabase — Cloud PostgreSQL Database]
        |
        |── folders, files, profiles tables ← queried directly from browser
        |── chat messages, announcements ← queried via frontend JS
        |── RLS policies ── enforce who can see what at database level
        |
 [Cloudflare R2 — File Storage]
        |── PDFs, images, videos, documents uploaded here
        |── served via /uploads/* route in server.js

 [AI Services]
        |── Gemini 1.5 Flash (primary)
        |── Groq (fallback if Gemini quota exceeded)
        |── Local sentence extractor (fallback if both AI services fail)
```

## 3. HTML Explanation

### What HTML Does in CLASS-APP

`index.html` is the **only HTML file the user sees**. It is 1,734 lines long and contains all the app's pages, buttons, sidebars, modals, and containers at once. JavaScript shows or hides each section depending on what page the user is on.

### Main Sections of index.html

#### Splash / Loading Screen
```html
<div id="splash-screen">
  <img src="icons/icon-512.png" alt="App Logo">
  <div class="loading-spinner"></div>
</div>
```
This is the logo+spinner that appears while the app loads. JavaScript hides it when loading completes.

#### Background Layer
```html
<canvas id="stars-canvas"></canvas>
<div id="custom-bg-overlay"></div>
```
- `stars-canvas` — an animated starfield drawn with JavaScript
- `custom-bg-overlay` — where the user's chosen background (gradient or custom image) is applied

#### Navigation Sidebar
```html
<nav id="sidebar" class="sidebar">
  <button id="hamburger-btn" onclick="toggleMenu()">☰</button>
  <ul id="nav-list">
    <li data-page="home" class="nav-item">Home</li>
    <li data-page="lobby" class="nav-item">Lobby</li>
    ...
  </ul>
</nav>
```
The sidebar contains all navigation links. Clicking a `nav-item` calls `goToPage()` in JavaScript.

#### Page Containers
```html
<div id="home-page" class="page active">...</div>
<div id="lobby-page" class="page">...</div>
<div id="file-summarizer-page" class="page">...</div>
```
Every feature has its own `<div>` container with `class="page"`. Only the active page is visible. Pages are switched by JavaScript toggling the `active` class.

#### Modals (Popup Dialogs)
```html
<div id="alert-modal" class="modal-overlay">
  <div class="modal-box">
    <p id="alert-message"></p>
    <button id="alert-ok-btn">OK</button>
  </div>
</div>
```
Instead of browser popup alerts (which look ugly), the app has custom modals for alerts, confirmations, and text input.

#### Audio Element
```html
<audio id="notification-sound" src="..."></audio>
```
Used to play notification sounds when messages arrive.

#### Script Loading (at bottom of index.html)
```html
<script src="https://cdn.socket.io/..."></script>
<script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js"></script>
<script src="features/logging-in/loading-components.js?v=13"></script>
<script src="features/logging-in/shell-controls.js?v=17"></script>
<script src="script.js?v=149"></script>
<script src="features/updates/changelog.js?v=52"></script>
...
```
Scripts are loaded at the bottom so the HTML renders first. The `?v=N` numbers force browsers to re-download files when they change.

## 4. CSS Explanation

### What CSS Does in CLASS-APP

`style.css` (5,671 lines) styles every visual element. It controls:
- Colors and themes (glassmorphism, dark background)
- Layout (how elements are arranged)
- Animations (fade in, slide up, pulse effects)
- Responsiveness (how the app looks on phones vs. computers)

### Main Style Sections

#### CSS Variables (Custom Properties)
```css
:root {
  --mountain-color: #4a90d9;
  --ocean-color: #00b4d8;
  --bg-dark: #020617;
  --glass-bg: rgba(255,255,255,0.05);
}
```
CSS variables let one color value be reused everywhere. Changing `--ocean-color` in one place updates every element using it.

#### Glassmorphism
The "glass card" effect seen throughout the app:
```css
.card {
  background: rgba(255, 255, 255, 0.05);
  backdrop-filter: blur(12px);
  border: 1px solid rgba(255,255,255,0.1);
  border-radius: 16px;
}
```
This creates semi-transparent, frosted-glass looking boxes.

#### Flexbox Layout
```css
.flex-row {
  display: flex;
  flex-direction: row;
  align-items: center;
  gap: 12px;
}
```
Flex is used to arrange buttons and cards side by side or in rows.

#### Grid Layout
Used for card grids (like the tools page or subject cards):
```css
.cards-grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(160px, 1fr));
  gap: 16px;
}
```
This creates a responsive grid where cards automatically wrap to the next line on smaller screens.

#### Media Queries (Responsive Design)
```css
@media (max-width: 768px) {
  .sidebar {
    width: 100%;
  }
}
```
Media queries change the layout based on screen size. Below 768 pixels wide (typical phone width), the sidebar becomes full-width.

#### Z-index (Layer Control)
```css
.sidebar { z-index: 100; }
.modal-overlay { z-index: 200; }
.splash-screen { z-index: 9999; }
```
Z-index controls which elements appear on top of others. Higher number = appears in front.

### Important CSS Concepts Used in This App

| Term | What it Means | Example Use in App |
|------|--------------|-------------------|
| `class` | A reusable style label | `.nav-item` styles all sidebar links |
| `id` | A unique style label (one element only) | `#sidebar` styles the one sidebar |
| `selector` | The target of a CSS rule | `.page.active` targets active pages only |
| `flex` | Layout method for rows/columns | Navigation bar, button groups |

| `animation` | CSS-controlled movement over time | Pulse effects, fade in, slide up |

| `glassmorphism` | Frosted-glass card effect | Feature cards, modals |
| `overlay` | Semi-transparent dark layer covering screen | Behind modals, blocking the background |

| `pointer-events: none` | Makes element unclickable (doesn't intercept mouse/touch) | Hidden pages (so background buttons can't be clicked) |

### How Buttons Work

Buttons in CLASS-APP work in two ways:

**Method 1: Inline onclick (older style)**
```html
<button onclick="toggleMenu()">☰</button>
```
The button calls the function directly in HTML. The function must be on the `window` object.

**Method 2: Event Listener (modern style)**
```javascript
document.getElementById('save-btn').addEventListener('click', function() {
  saveNote();
});
```
The button is connected to a function in JavaScript.

> ⚠️ **Important Bug Pattern:** If an inline onclick calls a function that is NOT attached to `window`, clicking the button does nothing (no error shown). This is a common bug in this app.

### How Pages Open and Close

Pages are `<div>` elements with class `"page"`. Only one is visible at a time.

```javascript
window.goToPage = function(pageName) {
  // 1. Hide all pages
  document.querySelectorAll('.page').forEach(p => {
    p.classList.remove('active');
  });

  // 2. Show the selected page
  document.getElementById(pageName + '-page').classList.add('active');

  // 3. Initialize the page's module if needed
  if (pageName === 'file-summarizer') {
    window.fileSummarizerModule?.init();
  }
};
```

### How Modals Work

Instead of `alert()`, `confirm()`, and `prompt()` (browser default popups), the app uses custom modals:

```javascript
window.customAlert = function(message) {
  document.getElementById('alert-message').textContent = message;
  document.getElementById('alert-modal').classList.add('active');
};
```

### How Authentication Works in JS

1. User enters username + password on the login screen
2. JS sends `POST /api/login` to the backend
3. Backend returns a **JWT token** (a string of encrypted data)
4. JS saves the token: `localStorage.setItem('classAppToken', token)`
5. Every future request includes: `Authorization: Bearer <token>`

### How localStorage / sessionStorage is Used

| Key | Location | Purpose |
|-----|----------|---------|
| `classAppToken` | localStorage | JWT auth token (persists across browser close) |
| `classAppUser` | localStorage | Current user's username |
| `notepad-notes` | localStorage | Offline notepad backup |
| `fs-quiz-settings` | localStorage | File Summarizer quiz preferences |
| `reviewers-sort-by` | localStorage | Sort preference for reviewer board |
| `notepad-imported-to-cloud` | localStorage | Whether user has imported local notes to cloud |

### How Event Listeners Work

An event listener waits for something to happen (a click, a keypress, a scroll) and then runs a function.

```javascript
// Listen for the Enter key in the chat input
chatInput.addEventListener('keydown', function(event) {
  if (event.key === 'Enter') {
    sendMessage();
  }
});
```

### How API Calls Work (fetch)

```javascript
// Example: Login request
const response = await fetch('/api/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ username: 'Student1', password: 'mypassword' })
});

const data = await response.json();
// data.token = the JWT token
```

`fetch()` sends HTTP requests from the browser to the server. `await` means "wait for the response before continuing."

### How Errors Are Handled

The app uses `try/catch` blocks:
```javascript
try {
  const data = await fetch('/api/something').then(r => r.json());
  // use data
} catch (error) {
  customAlert('Something went wrong: ' + error.message);
}
```

## 8. Authentication Explanation

### How Login Works

1. **Student fills in username and password** on the login screen
2. **JavaScript sends** `POST /api/login` with the username and password
3. **Server checks the password** using bcrypt (more on this below)
4. **If correct**, the server creates a **JWT token** (a digital ID card)
5. **JavaScript saves the token** in `localStorage` as `classAppToken`
6. **Every future request** includes `Authorization: Bearer <token>` in headers
7. **Server validates** the token on every protected route

### How Registration Works

1. Student fills in desired username and password
2. JavaScript sends `POST /api/register`
3. Server hashes the password with **bcrypt** (12 rounds)
4. Server creates the profile in Supabase database
5. Server returns a JWT token → user is immediately logged in

### How Logout Works

The app clears the token from localStorage:
```javascript
localStorage.removeItem('classAppToken');
localStorage.removeItem('classAppUser');
```
Without the token, the user is treated as logged out.

### How Sessions Work

- Sessions are stored in **localStorage** (stays even after browser is closed)
- The token expires after **7 days**
- `session-manager.js` auto-refreshes the token every 30 minutes
- If the user is idle for 25 minutes, a warning banner appears
- After 30 minutes of idle, the app logs them out automatically
- If the same account logs out in another browser tab, the current tab detects it and logs out too

### How User Profiles are Detected

After login, the app calls `/api/session` to verify the token and get user info:
```javascript
const res = await authFetch('/api/session');
const { username, isAdmin } = await res.json();
```

### How Admin Checking Works

The server checks if a username is in the `admins` table in Supabase:
```sql
SELECT 1 FROM public.admins WHERE username = $1
```
If found, `isAdmin = true`. Admins can see extra UI elements and access admin-only API routes.

## 9. Hash, Salt, Password, and Security

### What is a Hash?

A **hash** is a one-way transformation. You feed a password in, and you get a long scrambled string out. You cannot reverse it to get the original password back.

Example:
```
Password:  "mypassword123"
Hash:      "$2b$12$lX9R8kP7mN2qF5tH0wE1bO..."
```

The same password always produces a different hash (because of the salt — explained below), which means even if two students have the same password, their hashes look completely different.

### What is a Salt?

A **salt** is a random string added to a password before hashing. This prevents "rainbow table attacks" (where an attacker has a giant list of pre-computed hashes).

```
Password + Salt → Hashed Result
"mypassword123" + "random_chars_xyz" → "$2b$12$lX9R8kP7..."
```

In CLASS-APP, bcrypt automatically generates and stores the salt **inside the hash string**. You don't need to handle it separately.

### Why Passwords Must NOT Be Stored as Plain Text

If the database is stolen and passwords are stored as plain text:
- Attacker sees `"mypassword123"` directly
- They can log in as any user immediately
- Users who reuse passwords on other sites are also compromised

With hashing, an attacker only sees scrambled strings they cannot reverse.

### How Password Hashing Works in CLASS-APP

```javascript
// When registering (server.js):
const hash = await bcrypt.hash(password, 12);
// 12 = "cost factor" — higher = slower = harder to brute-force

// When logging in (server.js):
const match = await bcrypt.compare(enteredPassword, storedHash);
if (match) {
  // Login successful
}
```

### Legacy SHA-256 to bcrypt Upgrade

The app previously used SHA-256 (weaker) for passwords. It now auto-upgrades old accounts:
```javascript
function shouldUpgradePasswordHash(hash) {
  return !hash.startsWith('$2b$'); // $2b$ = bcrypt prefix
}
// If SHA-256 hash detected: re-hash with bcrypt on next successful login
```

### Does CLASS-APP Handle Password Hashing Directly?

**Yes** — the backend (`server.js`) uses `bcryptjs` to hash and verify passwords. Supabase Auth is NOT used for the main login flow. The app has its own authentication system backed by Supabase as the profile database only.

```sql
-- Example: Only the folder owner or admin can delete a folder
CREATE POLICY "owner_or_admin_can_delete"
ON folders FOR DELETE
USING (owner = current_setting('app.username') OR class_app_is_admin());
```

**Key RLS Helper Functions:**
- `class_app_is_admin()` — checks if current user is in the `admins` table
- `class_app_can_view_folder(folder_id)` — checks folder permissions
- `class_app_can_edit_folder(folder_id)` — checks edit access

The frontend sets the current username in a request header (`x-class-username`), and the database reads it via `current_setting('app.username')` to enforce policies.

## 11. Storage and File Uploads

### Where Files Are Stored

CLASS-APP uses **Cloudflare R2** for file storage. R2 is compatible with Amazon S3's API and is used because it's cheaper (no bandwidth fees).

Files are stored in the `R2_BUCKET` bucket. Subfolders inside:
- `uploads/images/` — uploaded images
- `uploads/videos/` — uploaded videos
- `uploads/audio/` — audio files
- `uploads/documents/` — PDFs, DOCX, PPTX

### How File Upload Works (Step by Step)

1. User selects a file using `<input type="file">`
2. JavaScript creates a `FormData` object and appends the file
3. JavaScript sends `POST /api/upload` with auth headers and the FormData
4. Server receives the file via **multer** (a file upload middleware)
5. Server validates file type and size (max 50MB for video, 8MB for documents in summarizer)
6. Server uploads the file to Cloudflare R2 using the AWS S3 SDK
7. Server saves the file record (name, URL, folder_id) to Supabase `files` table
8. Frontend receives the file URL and shows it in the UI

### File Summarizer Upload Flow

1. User uploads PDF, DOC, DOCX, or PPTX (max 8MB)
2. Server extracts text:
   - **PDF** → `pdf-parse` library reads text
   - **DOCX/DOC** → `mammoth` library extracts text
   - **PPTX** → `adm-zip` opens ZIP, parses slide XML tags
3. Extracted text (max 50,000 characters) is sent to AI:
   - Gemini 1.5 Flash (primary)
   - Groq (if Gemini quota exceeded)
   - Local sentence extractor (if both fail)
4. AI generates: study notes, detailed summary, key concepts, terms, or quiz

### File Validation

**What is validated:**
- File type (extension): only .pdf, .doc, .docx, .pptx for summarizer
- File size: max 8MB for summarizer, 50MB for video uploads
- Text content: at least 1 character of extractable text (rejects image-only PDFs)

**What is NOT validated / risks:**
- MIME type not deeply verified (extension check only)
- No virus/malware scanning
- No image content moderation

### File Security — The `/uploads/*` Route

```javascript
// server.js: Serving files from R2
app.get('/uploads/*', async (req, res) => {
  // Fetch from R2 using the S3 SDK
  // Set safe Content-Type (never text/html or text/svg)
  // Set X-Content-Type-Options: nosniff header
  // For certain types, force download (attachment) instead of display (inline)
});
```

The `X-Content-Type-Options: nosniff` header prevents browsers from guessing the file type, which could allow an attacker to serve a JavaScript file disguised as an image.

1. Frontend: file → `POST /api/summarize-file`

4. Backend: return AI response

If `GEMINI_API_KEY` were in the frontend JavaScript (visible to anyone who views page source):


The YouTube API key is called server-side. The browser never sees the key — it only sends a search query to `/api/yt-search`.

Three fallback methods exist for YouTube:
1. Official YouTube Data API v3 (requires key, quota-limited)
2. Piped API (no auth needed, open source proxy)
3. InnerTube API (simulates a mobile YouTube client, no key needed)

## 13. PWA, Cache, and Service Worker

### What Makes CLASS-APP a PWA?

1. **manifest.json** — tells browsers the app can be installed
2. **sw.js** — service worker that caches files for offline use
3. **HTTPS** — required for service workers
4. **Icons** — proper 192×192 and 512×512 PNG icons

### What manifest.json Does

```json
{
  "name": "My School Portfolio",
  "short_name": "School Portfolio",
  "display": "standalone",        ← opens like a native app (no browser bar)
  "start_url": "/",
  "background_color": "#020617",  ← splash screen color
  "theme_color": "#0b1b3d",       ← phone status bar color
  "icons": [...]
}
```

When a user visits the app and Chrome/Safari detects a valid manifest + service worker, it may show an "Add to Home Screen" prompt.

### What sw.js Does

The service worker is a special JavaScript file that runs in the background (not on the main page). It intercepts all network requests and can serve files from cache.

**Key parts of sw.js:**

**1. Installation — caching files:**
```javascript
self.addEventListener('install', (event) => {
  event.waitUntil(
    caches.open(CACHE_VERSION).then((cache) => {
      return cache.addAll(ASSETS); // Download and cache all 92 files
    })
  );
});
```

**2. Activation — cleanup:**
```javascript
self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then((keys) => {
      return Promise.all(
        keys.filter(key => key !== CACHE_VERSION).map(key => caches.delete(key))
      );
    })
  );
});
```
When a new version is deployed, old caches are deleted so users get fresh files.

**3. Fetch — serving from cache:**
```javascript
self.addEventListener('fetch', (event) => {
  // Never cache /api/ calls (always fresh data)
  if (event.request.url.includes('/api/')) return;

  // For everything else: try network first, fallback to cache
  event.respondWith(
    fetch(event.request).catch(() => caches.match(event.request))
  );
});
```

### What Cache Version Means

```javascript
const CACHE_VERSION = "v1.5.84-20260511-tetris-restored";
```

Every time the app is updated, this string changes. The service worker detects the new version, deletes the old cache, and downloads fresh files.

### Why Cache Must Be Bumped After Updates

If you change `style.css` but don't bump the cache version, users will:
1. Download the new service worker
2. But the service worker still has the OLD CSS version in cache
3. Users see old styles until they manually clear browser cache

This is why every change requires updating `?v=N` in `index.html` AND `sw.js`, and changing `CACHE_VERSION`.

The app has `scripts/cache-bust.js` that runs automatically before deployment (`npm run prestart`) to stamp the cache version with the current date.

### How to Debug Cache Issues

1. Open Chrome DevTools → Application → Service Workers
2. Click "Update" to force-update the service worker
3. Click "Unregister" to completely clear the service worker
4. Then hard refresh: `Ctrl+Shift+R` (or `Cmd+Shift+R` on Mac)

### Push Notifications

The app supports Web Push notifications for alarms. This uses:
- **VAPID keys** — authentication keys for push services
- `web-push` npm package — sends notifications from the server
- `supabase/functions/check-alarms/index.ts` — Edge Function that checks if alarms are due and sends push

### PWA Jargon Explained

| Term | Simple Explanation |
|------|--------------------|
| **PWA** | A website that acts like a native app |
| **Service worker** | Background script that controls caching and push notifications |
| **Manifest** | JSON file that tells browsers how to install the app |
| **Cache** | Saved copies of files stored locally for fast/offline loading |
| **Cache busting** | Forcing browsers to download new file versions |
| **Offline mode** | App works (partially) without internet using cached files |

## 16. Common Bug Patterns in the App

### 1. The pointerEvents Ternary Bug (CRITICAL — documented in MUST-FIX)

**Location:** `script.js` ~line 3197  
**Symptom:** Buttons on hidden pages can still be triggered; weird behavior when navigating  
**Fix:** Change both branches of the ternary to `'auto'` and `'none'` respectively

### 2. Inline onclick Calling Undefined Function

**Symptom:** Button appears, hovers correctly (CSS works), but clicking does nothing. No error in console (or a "function not defined" error).  
**Cause:** HTML has `onclick="doSomething()"` but `doSomething` is not on `window.doSomething`.  
**Example:**
```html
<button onclick="openFolderExplorer(id)">Open</button>
```
```javascript
// Bug: function is inside a module scope, not on window
function openFolderExplorer(id) { ... }

// Fix: expose it
window.openFolderExplorer = openFolderExplorer;
```

### 3. Script Loading Order Problems

**Symptom:** Error like "customAlert is not defined" on page load  
**Cause:** A script tries to call a function from another script that hasn't loaded yet  
**How to check:** Look at script tag order in `index.html` — scripts run top to bottom

### 4. Old Cache Serving Outdated Code

**Symptom:** You deployed a fix, but users still see the old version  
**Cause:** Service worker still has old files in cache, and `CACHE_VERSION` wasn't updated  
**Fix:** Bump `CACHE_VERSION` in `sw.js` and bump `?v=N` for changed files in `index.html` AND `sw.js`

### 5. Duplicate Function Names

**Symptom:** Only one version of a function runs — unexpected behavior  
**Cause:** Two files define `function uploadFile()` — the second one overwrites the first  
**How to find:** `grep -n "function uploadFile" **/*.js`

### 6. Overlays Blocking Buttons

**Symptom:** Button is visible, but clicking it doesn't work — no function is called  
**Cause:** An invisible overlay `div` is on top of the button (z-index or position issue)  
**How to find:** Chrome DevTools → Inspect Element → look for invisible divs with high z-index

### 7. CSS pointer-events: none on Parent

**Symptom:** Button inside a container is not clickable even though it has a click handler  
**Cause:** Parent element has `pointer-events: none` which inherits to children  
**Fix:** Add `pointer-events: auto` to the specific button element

### 8. Supabase Errors Silently Failing

**Symptom:** Data doesn't save or load; no visible error  
**Cause:** `const { data, error } = await sb.from(...).select(...)` — `error` is never checked  
**Fix:** Always check: `if (error) { console.error(error); customAlert('Database error'); return; }`

### 9. RLS Permission Errors

**Symptom:** Supabase returns empty array or 403 error for valid queries  
**Cause:** Row Level Security policy blocks the request  
**How to debug:** Check Supabase dashboard → Table Editor → check RLS policies for the table

### 10. JavaScript Error Stopping the Rest of the File

**Symptom:** Everything below a certain line in a JS file stops working  
**Cause:** An uncaught runtime error stops execution  
**Fix:** Use `try/catch` around risky operations; check browser console for the exact error

### 11. Broken Imports (Modules Not Loading)

**Symptom:** `window.reviewersModule is undefined`  
**Cause:** The feature JS file wasn't loaded in `index.html` or failed to load  
**Fix:** Check the `<script>` tag exists, check for loading errors in the Network tab

### 12. Mobile Layout Conflicts

**Symptom:** Button is visible on desktop, invisible or unclickable on phone  
**Cause:** Fixed-position elements overlapping, 100vh including browser chrome on iOS, safe area not respected  
**Fix:** Use `env(safe-area-inset-*)` CSS variables for iOS; test on actual phone

### 13. Undefined Variables

**Symptom:** `Cannot read properties of undefined (reading 'username')`  
**Cause:** Code assumes `currentUser` is loaded but it isn't yet (async timing issue)  
**Fix:** Check if the variable is loaded before using it; use optional chaining `currentUser?.username`

### 14. Ana Cruz Demo Profile (Hardcoded Data)

**Location:** `coding-educational/coding-educational.js` (lines 420, 425, 437)  
**Issue:** A hardcoded demo student profile named "Ana Cruz" appears in lesson completion data  
**Risk:** Confuses real data with demo data; should be clearly labeled as mock/demo data
